# GameFold PC V0.8.2 双屏按钮焦点层级设计

## 目标

仅调整首页顶部“双屏显示”按钮的聚焦视觉层级：焦点框作为底层显示在按钮外围，48dp 双屏按钮本体完整绘制在焦点框上方。

快速上手和高级设置按钮保持现有焦点效果；不修改按钮位置、按钮图片、点击区域、控制器导航、双屏开关状态或生命周期逻辑。

## 现状

`HeaderPixelAction` 当前先绘制双屏按钮的完整 48dp 图片，再绘制同尺寸焦点框。由于焦点框位于最后一个子层，它会覆盖到按钮图片前面。

双屏按钮通过 `ownsFrame = true` 与另外两个组合按钮区分，因此可以只在这个分支调整层级，不改变共享组件的其他调用方。

## 选定方案

1. `HeaderPixelAction` 外层布局和点击区域继续保持 48dp。
2. 当 `ownsFrame && focused` 时，先绘制一个居中的 56dp 焦点底层。
3. 焦点底层使用 `requiredSize(56.dp)`，避免被父级 48dp 约束压回同尺寸；父级不裁剪，焦点框仅从按钮四周露出 4dp。
4. 随后按原尺寸绘制 48dp 双屏按钮图片，使按钮面、图标和状态图完全位于焦点层上方。
5. `ownsFrame == false` 的快速上手和高级设置仍使用现有前景焦点绘制顺序。

## 验收

- 双屏按钮聚焦时，焦点框位于按钮后方，只在外围可见。
- 双屏按钮本体没有被焦点颜色覆盖，大小仍为 48dp。
- 双屏按钮的触控热区、DPAD 焦点和点击行为不变。
- 快速上手和高级设置按钮的视觉与交互不变。
- 源码契约测试、完整单元测试和 `git diff --check` 通过。
- 构建独立 RC3 并在 vivo 首页检查聚焦与非聚焦两种状态；不清数据或权限。

## 范围限制

不修改 `gameFoldNsFocusFrame` 的全局实现，不新增图片资源，不调整首页 Header 间距，也不改动 RC2 已通过的双屏生命周期状态机。
